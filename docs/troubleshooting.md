# 故障排查与维护

[返回使用说明](../README.md)

## 看不到 Settings 或链接显示 404

确认当前登录的是仓库所有者，或拥有管理员权限。Fork 用户需要打开自己仓库的 Settings，而不是上游仓库的设置。

## 配置检查失败

在 Actions 的「检查账号配置（离线）」中查看缺失的是哪组变量。邮箱和密码必须成对；删除账号时也要同时删除两个 Secret。JSON 不能包含注释、单引号或尾随逗号，密码中的引号和反斜杠必须正确转义。

如果刚从编号式切换到 JSON，且重复配置的密码不同，请删除已被替代的编号式 Secrets。不要把真实 JSON 内容贴到 Issue。

## 邮箱或密码错误

先在浏览器确认可以登录 AbleSci。GitHub 中更新对应的 Repository secret，然后手动运行。Secret 名字填在 Name，真实值填在 Secret，值不需要额外包引号。

程序会去掉 BOM 和首尾换行；邮箱还会清理首尾空白，密码的首尾空格会保留。如果误粘贴空格，请在 GitHub 网页重新填写。Secret 无法读回，不要尝试在日志中打印验证。

## 被要求验证码

在浏览器正常登录并完成验证码，核对 Secret 后再手动运行。脚本遇到验证码直接结束该账号的流程，不反复尝试，也不会自动绕过验证。浏览器验证成功不保证另一个网络环境可以立即免验证；如果持续出现，需要人工处理或暂停自动签到。

## 网络、CSRF 或异常响应

本地执行 `python ablesci_signin.py --check`，可独立检查登录页是否可达、能否提取 CSRF。它不会验证密码，也不代表实际签到必定成功。

HTTP 错误、非 JSON 响应、JSON 结构不匹配会明确报错，不输出响应正文。网站可能维护、调整接口或返回拦截页面，先确认浏览器能正常访问。

维护入口为 `ablesci/client.py`：CSRF 使用 HTMLParser 提取表单 `_csrf` 或 meta `csrf-token`，兼容旧的 `csrf-val`；不依赖属性顺序。若接口变化，先补充模拟响应的回归测试再调整解析。`code` 必须是整数，不能根据非空消息猜测成功。

## 今天已经签到，但任务显示失败

只把网站明确表示“今天已签到”的消息视作成功，含有一个“已”字的其他拒绝消息不会被误判。遇到新文案，请提供打码后的说明文字；不要提供 Cookie、CSRF、密码或完整响应内容。

签到请求超时可能发生在网站已完成操作之后。脚本不会立即重复提交这次签到请求，下一次手动运行如果返回已签到，会按成功处理。积分或连签天数无法解析时显示 `-`，不会把已经成功的签到改成失败。

## 定时任务没有运行

1. 确认 workflow 在默认分支 `master`，Actions 已启用，且每日签到工作流处于启用状态。
2. Fork 后通常需要先在 Actions 页面允许工作流运行。
3. 公开仓库连续 60 天没有仓库活动时，定时工作流可能被自动停用。在 Actions 选择工作流，通过 **Enable workflow** 重新启用，再手动运行验证。
4. 若显示启用、手动运行成功，却连续多天没有 `schedule` 运行，检查原定时触发账号是否已删除、停用或显示为 `ghost`。由当前有写入权限的账号提交一次实际改变 cron 表达式的修改，重新绑定触发账号；仅修改注释、手动运行或查看 active 状态不能完成这项验证。参见 [GitHub 官方排查说明](https://docs.github.com/en/actions/how-tos/troubleshoot-workflows#scheduled-workflow-stopped-running)。
5. GitHub 调度可能延迟或丢弃任务，尤其在整点负载高时。08:17 是触发时刻，不是签到承诺时间；还要计入项目额外随机等待和排队时间。
6. 如需调整时刻，修改 workflow 中的 cron。它按 UTC 计算，北京时间减 8 小时；也可改为非整点触发以避开整点负载。

仅有定时执行记录不应被当成永远保持仓库活跃的保证。详见 [GitHub schedule 文档](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。

## 邮件未收到

查看「执行签到」日志中的邮件配置或发送警告。QQ 邮箱使用 SMTP 授权码；465 使用 SSL，587 使用 STARTTLS。确认服务商允许用户名和密码认证，并检查收件箱垃圾邮件目录。

`MAIL_WHEN=failure` 在全部签到成功时不会发信，`never` 完全关闭。账号配置检查失败时还没进入签到和通知阶段。邮件发送失败不改变签到退出码，所以需要同时查看邮件日志。

## 仓库转移之后

进入新地址的 Settings 和 Actions，确认 Secrets、仓库变量及定时工作流状态，并手动运行一次。若旧账号已经失效，由新账号修改一次 cron。接下来检查首个 `schedule` 运行的触发账号和结果，确认已经恢复；手动运行只能证明当前配置和签到接口可用。

本地克隆更新远程地址：

```sh
git remote set-url origin https://github.com/leezc250110/ablesci-daily.git
```

本项目重构的单元测试不会读取仓库 Secrets、登录网站或真实发送邮件。合并后需要由有权限的维护者在默认分支手动运行，完成真实账号验证。
